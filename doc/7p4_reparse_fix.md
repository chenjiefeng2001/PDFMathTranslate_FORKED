# 7P4 — 并页逐页重解析:把 201 个叠在一起的块变回 29 个,并真的译出来

修复对象是 7P3 遗留的唯一用户可见损失:被隔离的目录页**整页不翻译**。

---

## 1. 为什么单独重解析能解决

实测（mp2e 前 50 页）：MinerU 把**源第 7~14 页共 8 页目录**压成第 7 页的**一个**
``index`` 块 / **327 行**，而该页高只有 665pt —— 行距 2.03pt。它是**把多页当成一页看**
的产物；单独喂一页进去就没有"多页"可并。

这是唯一能拿回那 8 页目录的办法（隔离只能让它们不翻译）。

### 为什么复用既有切片机制

并页**正是页号错配造成的**。``adapter.parse`` 里已有
``_slice_pdf_for_pages`` + ``_remap_magicpdf_result_pages``（预切片 → 分析 → 页号还原）。
自己再造一套页号映射等于把同一个缺陷再写一遍 —— 所以只交付页号，拿回**已还原**的结果。

## 2. 实跑结果（log）

```
[magicpdf] WARNING 版面模型把多个源页并进了同一 render 页
           (page 6: 327 lines, 2.03pt/line, implies 5.83 page(s))
[magicpdf] INFO    page 6 re-parsed cleanly (2 block(s)); quarantine lifted
[magicpdf] INFO    all 1 collapsed page(s) re-parsed cleanly; no page needs isolation
```

**没有隔离任何页** —— 重解析直接救回来了。

| 指标 | BEFORE(7P0) | 7P3(隔离) | **7P4(重解析)** |
|---|---|---|---|
| 引擎 | magicpdf | magicpdf | **magicpdf** |
| 单页最多块数 | **201** | 201 | **29** |
| 第 6 页译出中文的块 | — | **0** | **29 / 29** |
| 叠印页(渲染器口径) | 11 | 10 | 11 |
| 越界 span | 0 | 0 | 0 |
| render-plan 块数 | 621 | 621 | 449 |

第 6 页从 **201 块（全部互相覆盖、原文与译文都查不到）**变成 **29 块、29 块全译出中文**，
成品 PDF 第 7 页里能找到"目录"。

块数从 621 降到 449 是**正确**的：原来那 201 块里绝大部分是 MinerU 把 8 页目录的
行重复塞进同一页框产生的伪块，不是真实内容。

## 3. 守卫

重解析的结果**必须**不再触发并页检测才准进主链路：

```python
still = detect_merged_pages(sub)
if still:
    ...  continue   # 换回来的还是被压扁的结果，且页号已错位过一次
```

任何一步失败（切片失败、重解析又并页、解析器缺席、脏页号）都返回空字典 → 调用方
**退回隔离**。

换回 `results` 必须**按页号**而不是按位置：`results` 是文档序的完整列表而 `reparsed`
只含几页，按顺序替换会把第 7 页写进第 3 页的槽位 —— 那正是并页本身的成因。换不进去的
页由 `_swap_reparsed_pages` 的返回值挡住，不会落进「既没隔离、也没内容」的最坏组合。

## 4. 测试

20 个新测试，变异 6/6：按位置换页、虚报换成功、完全不换、采用仍然并页的结果、
把多页打包成一次调用、外层兜底改成 `raise`。

**两个变异体第一轮没杀掉**，都是测试写法的问题，已记录：

- "不换回 results"：我最初把换回逻辑写在 `magicpdf_cli` 的调用点里，测试只测
  `_reparse_merged_pages` 的返回值 —— 而返回值不经过那段代码。抽出
  `_swap_reparsed_pages` 并直接测它才杀掉。
- "外层兜底改成 raise"：脏页号那条测试写成「返回 dict 或抛 TypeError 都算过」，
  于是把兜底改成 `raise` 也算合法。收紧为必须返回 `{}` 才杀掉。

## 5. ⚠ 墙钟 130s 仍然是缓存

复测 130s vs 基线 5341s，**但 `--ignore-cache` 没有真正传进去**
（`7p2_verify_run.py` 不支持该参数），翻译缓存仍然命中。真实整篇耗时仍未测。
`doc/7p2_compare_runs.py` 会把 `translation_cache_reused` 标出来，正是为了防止这个
数字被读成提速。
